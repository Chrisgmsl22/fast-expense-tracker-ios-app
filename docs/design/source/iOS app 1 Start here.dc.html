README.md· fast-expense-ios (proposed repo name)

Fast Expense for iPhone

Native iOS client for Fast Expense, a personal expense tracker in Mexican pesos for people who split some of their costs with a partner.

Swift 6 · SwiftUI · iOS 18+ · MXN · English / Español

Status: designed, not built yet. Every screen is designed in the FET design canvas (103 screens). The build starts when the web app's /api/v1 and the OAuth consent page are live.

The web app (fast-expense-tracker) stays the source of truth. This app is a fast, native front end on top of its API: it signs in through the web, reads and writes through /api/v1, and never does the money math itself.

What it does

  • Log a purchase in seconds. A floating + opens the Add sheet from any screen: expense, card payment, points redemption, "I paid Sam" or "Sam paid me".
  • See your real share. A shared expense counts only your share toward your budget (for example 68%), and the full charge still counts toward the card.
  • Stay on your plan. Income splits into three buckets: Essentials 50%, Discretionary 25% and Savings 25%. You can change the split.
  • Settle up. One running balance tells you what your partner owes you, or what you owe them.
  • Track card balances. Charged − payments − points redeemed, per card and per month.
  • Hide amounts. One eye toggle masks every figure in the app.

Money rules this app must not break

  1. A shared expense counts only my share toward the budget. The full charge still counts toward the card balance.
  2. The budget splits income into Essentials / Discretionary / Savings (50 / 25 / 25 by default). Savings is its own bucket.
  3. A card payment is not spending. It lowers a card balance and never changes budget totals.
  4. Settlement tracks what the partner owes the user and what the user owes the partner.
  5. The phone never calculates totals. Every figure such as actualExpenditure comes from the server. The app only formats it.

How it works

Area Choice
UI SwiftUI, @Observable view models, NavigationStack per tab
Navigation Tab bar: Dashboard · Expenses · Money · Settings, plus a floating + for Add
Sign-in OAuth 2.1 + PKCE in ASWebAuthenticationSession on the web /login page, then a consent screen
Tokens Keychain. Access token lasts 1 hour, refresh token 30 days. Refresh is silent
API async/await URLSession client for /api/v1, Codable DTOs
Money Decimal everywhere, formatted as $1,000.00 in es_MX / en_US
Writes Optimistic rows with a pending state. A failed write rolls back and shows a toast
Strings String Catalog (Localizable.xcstrings), English and Spanish
Type Geist and Geist Mono, bundled (SIL Open Font License)

The app does not include Sign in with Apple, Google sign-in, passkeys, Face ID or two-factor auth. Spec 0009 puts them out of scope.

Getting started (proposed)

Requirements: Xcode 26 or later, an iOS 18 simulator or device, and the web app running locally (see the web repo's README).

  1. Clone the repo and open FastExpense.xcodeproj.
  2. Copy Config/Local.example.xcconfig to Config/Local.xcconfig and fill it in:

ini API_BASE_URL = http:/$()/localhost:3000/api/v1 OAUTH_CLIENT_ID = fast-expense-ios-dev OAUTH_REDIRECT_SCHEME = fastexpense

  1. Register the dev client in the web app, using the redirect URL fastexpense://oauth/callback.
  2. Run the FastExpense scheme. The first sign-in opens the web login in a browser sheet.

Local.xcconfig is ignored by git. Don't commit real client IDs or tokens.

xcodebuild test -scheme FastExpense -destination 'platform=iOS Simulator,name=iPhone 17'
  • Unit tests: money formatting, masking, DTO decoding, token refresh, and the optimistic-write queue.
  • UI tests: sign-in with a stubbed auth session, logging an expense, the shared-expense share line, and settlement actions.
  • No test may assert a total the app computed itself. Totals come from API fixtures.

Privacy

Fast Expense keeps your data in your own account on the web app's database. The app will ship with no ad or tracking SDKs. The privacy policy page (CHORE-37) explains what is stored, where, who can read it, and how to ask for deletion. The App Store listing links to it.
